# Fun-ASR-Nano 微调记录

目标：用数据微调 Fun-ASR-Nano-2512（0.8B，Qwen3-0.6B LLM + 音频编码器），
提升识别准确率。下含两次实验：**AISHELL-1 真实数据（主体）** 与 **迷你数据流程验证**。

---

# 一、AISHELL-1 微调（2026-09-17，RTX 4060 Laptop 8GB）

## 结果

| 项目 | 结果 |
|---|---|
| CUDA 可用 | ✅ `torch 2.14.0+cu126`，识别到 **NVIDIA GeForce RTX 4060 Laptop GPU** |
| 数据 | 官方人工校对标注，训练 **11,986 条 / 15.2 小时**，验证 **3,000 条 / 3.8 小时**（说话人独立） |
| 数据准备耗时 | **3 分钟**（流式按需解压，2.1GB）；对比"下载 15.58GB 整包再解压 14 万文件"约 40 分钟 |
| 训练配置 | adaptor-only（冻结 encoder+LLM），batch_size=8，lr=1e-4，3 epoch |
| 训练耗时 | **19.8 分钟**（0.256 秒/步，1499 步/epoch ≈ 6.4 分钟/epoch），含模型加载共约 26 分钟 |
| 显存峰值 | **1.06 GB / 8 GB**（batch_size=8 时，仍有大量余量） |
| 训练中验证精度 | ep1 0.9824 → ep2 **0.9834（最佳）** → ep3 0.9793 |
| 评测集 | dev 随机抽 **1,200 条**（人工标注） |
| **CER** | **3.20% → 1.91%（相对 −40.4%）** |
| 整句正确率 | 79.67% → 82.58% |
| 逐条变化 | 变好 76 条 / 变差 39 条 / 持平 1,085 条 |

## ⚠️ 关键：这个提升不代表识别能力变强了

拆开看增益来源（`analyze_gain.py`）：

| 子集 | 条数 | 微调前 CER | 微调后 CER | 相对变化 |
|---|---|---|---|---|
| 全部 | 1200 | 3.20% | 1.91% | **−40.4%** |
| 数字书写习惯相关 | 44 | 34.11% | 0.87% | **−97.4%** |
| 其余（真实识别） | 1156 | 1.91% | 1.95% | **+1.9%** |

AISHELL-1 的标注把数字写成汉字（`一点一一五亿元`、`二零一一年`），而基座模型习惯输出
阿拉伯数字（`1.115亿元`、`2011年`）。微调后模型**学会了标注方的书写习惯**，这部分贡献了
几乎全部 CER 降幅；在其余 1156 条上 CER 基本持平（1.91% → 1.95%，略退）。

另一个副作用：**微调后模型几乎不再输出标点**（输出含标点的句子比例 83.3% → 0.3%），
因为 AISHELL-1 标注本身不含标点，模型把这个习惯也学了过去。本 CER 已归一化去标点故不受影响，
但**实际使用会明显退化**（需要另接标点模型）。

同时也有少量真实退步案例：`他/她` 混用、`须/需`、`藏獒→造谣`、`迁出→迁除`。

## 结论与建议

1. **流水线完全跑通且很快**：15.2 小时数据 3 轮只要 20 分钟，显存占用 1/8。要跑全量 178 小时
   也只需约 1.4 小时/epoch，瓶颈完全不在算力。
2. **AISHELL-1 不适合作为"提升识别能力"的微调数据**：它是通用朗读语料，基座模型本就很强
   （基线 CER 仅 3.2%），而它的标注约定（汉字数字、无标点）与产品想要的输出格式相反，
   微调后第一件事是"把模型教坏"——丢掉标点、数字改写。
3. **要做真正有用的微调，训练标注必须按"期望的输出格式"来写**：数字用阿拉伯数字、
   带标点、专有名词写准。数据来源应该是**领域真实录音**（会议、客服、直播等），
   而不是通用朗读语料。这样模型才会同时学到"领域词"和"正确输出格式"。
4. 若仍想用 AISHELL-1 的量级练手，建议先把标注转成目标格式（数字转阿拉伯数字 + 用 ct-punc
   补标点）再训练，否则会得到上面这种"分数好看、实用变差"的结果。

## 数据准备（可复现，3 分钟拿到 1.5 万条）

AISHELL-1 在 ModelScope 上有镜像（`OmniData/AISHELL-1`，实测 **23.7MB/s**）；
OpenSLR 原站只有 1.2MB/s，不要用。**注意归档不是扁平 wav 结构**：
`data_aishell.tgz` 里是 `data_aishell/wav/S0724.tar.gz` 这种"每说话人一个嵌套 tar.gz"
（约 44MB / 354 条），内层路径为 `dev/S0724/BAC009S0724W0121.wav`（16kHz 单声道 16bit，平均 4.6 秒）。

所以用**流式按需解压**（`dataset/extract_aishell.py`）：边下边解，拿到目标条数立即中断下载，
不必落 15.58GB 压缩包，也不必解压全部 14 万个文件。

```powershell
# 1) 流式解压（curl 供流，脚本按目标条数主动断流）
curl -sL "https://www.modelscope.cn/api/v1/datasets/OmniData/AISHELL-1/repo?Revision=master&FilePath=raw%2F33%2Fdata_aishell.tgz" ^
  | .\funasr_env\Scripts\python.exe dataset\extract_aishell.py 12000 3000

# 2) 官方人工校对标注（CSV，约 10 秒下完）配 wav 生成清单
.\funasr_env\Scripts\python.exe dataset\build_lists.py

# 3) 转 ChatML jsonl
cd finetune\fun_asr_nano
..\..\funasr_env\Scripts\python.exe scp2jsonl.py ++scp_file=C:/Users/iiiis/Desktop/FunASR/dataset/list/train_wav.scp ^
    ++transcript_file=C:/Users/iiiis/Desktop/FunASR/dataset/list/train_text.txt ^
    ++jsonl_file=C:/Users/iiiis/Desktop/FunASR/dataset/list/train.jsonl
```

# 二、迷你数据版流程验证（8 条 / 2.3 分钟）

## 本次实测结果（2026-09-17）

| 项目 | 结果 |
|---|---|
| CUDA 可用 | ✅ `torch 2.14.0+cu126`，`torch.cuda.is_available()=True`，识别到 **NVIDIA GeForce RTX 4060 Laptop GPU** |
| 训练耗时 | **约 53 秒**跑完 10 epoch（70 个 iteration，7 条训练样本）；含模型加载共约 75 秒 |
| 显存峰值 | **1.06 GB / 8 GB**（batch_size=1 + accum_grad=2，非常宽裕，无 OOM） |
| 验证指标 | 训练日志 best acc 0.7273（token 级） |
| 产出 | `outputs/model.pt.avg3`（3 个最优 checkpoint 平均）+ `outputs_merged/`（合并基座后的可用完整模型） |
| 解码验证 | 基线 与 微调后 在 8 条样本上 CER 均 13.3%（逐条完全一致） |
| 残留清理 | 释放 13.3 GB（wheel 包 2.5G、`~orch` 520M、中间 checkpoint 与测试产物） |

**结论**：训练/解码/合并全流程跑通，环境与脚本都没问题。但**效果层面无差异**是预期内的：
数据只有 2.3 分钟、10 epoch、实际只发生约 35 次参数更新，adaptor 权重最大变化仅 ~5e-6，
不足以改变 greedy 解码结果。要真正提升专有名词识别，必须换成人工校对的领域数据（几十分钟起）。

## 使用步骤

1. 双击 `finetune_local.bat` 开始训练（等价命令见文件内注释，也可手动跑）。
   - 文件里先检查 `torch.cuda.is_available()`，通过后启动训练。
   - 策略：冻结 audio_encoder 和 LLM，只训 audio_adaptor（官方对 <1000 小时数据的推荐）。
   - 当前参数：`batch_size=1` + `accum_grad=2`（8GB 显存实测峰值仅 1.06GB）。
2. （降级方案）显存不足时双击 `lora_local.bat`：只训 LLM 里注入的 LoRA 适配器，显存最省。
3. **解码验证（重要，官方 decode.py 直接跑会得到乱码）**：
   ```powershell
   # ① 合并权重：基座 + 微调 checkpoint → outputs_merged（生成可直接加载的完整模型目录）
   .\..\..\funasr_env\Scripts\python.exe merge_ckpt.py ++ckpt="outputs/model.pt.avg3" ++out_dir="outputs_merged"

   # ② 解码
   .\..\..\funasr_env\Scripts\python.exe decode_ft.py ++base_model="outputs_merged" ^
       ++scp_file="..\data\all_wav.scp" ++output_file="..\data\output_finetuned.txt"

   # 基线对比（不加微调权重）
   .\..\..\funasr_env\Scripts\python.exe decode_ft.py ^
       ++base_model="C:/Users/iiiis/.cache/modelscope/models/FunAudioLLM--Fun-ASR-Nano-2512/snapshots/master" ^
       ++scp_file="..\data\all_wav.scp" ++output_file="..\data\output_baseline.txt"
   ```

## 踩坑记录（下次直接看这里）

1. **torchrun 在 Windows 上起不来**：`torch.distributed.DistStoreError: use_libuv was requested but PyTorch was built without libuv support`
   （`USE_LIBUV=0` 也无效）→ 绕开 torchrun，直接 `python -m funasr.bin.train_ds ++...`；
   train_ds 从环境变量读 `RANK/LOCAL_RANK/WORLD_SIZE`，缺省即单卡模式。
2. **微调 checkpoint 不含冻结权重**：训练日志里 3110 条 `key: llm.xxx matching: llm., not save it`，
   `model.pt.avg3` 里只有 audio_encoder / audio_adaptor / ctc（1036 键，缺 LLM 的 3111 键）。
3. **不能直接用 `init_param=<微调ckpt>` 解码**：该参数是覆盖式加载，会顶掉基座权重加载路径，
   缺 LLM 权重 = 随机初始化 → 输出 `"regnregnregn..."` 这类重复垃圾 token。
   正确做法：用 `merge_ckpt.py` 先合并（基座 1347 键 + 覆盖 1036 键），再按普通本地模型加载。
4. **合并目录必须带 `Qwen3-0.6B` 子目录**：基座 config.yaml 里 tokenizer 用相对路径 `Qwen3-0.6B`，
   缺了会去连 huggingface.co 报 `OSError: We couldn't connect to 'https://huggingface.co'`。
5. **pip 换 torch 版本是"先卸后装"**，下载中断会让环境裸奔；本次改为先把 wheel 下到本地再离线安装。
6. **`accum_grad` 无 epoch 末兜底**：funasr 只在 `(batch_idx+1) % accum_grad == 0` 时更新参数，
   7 条样本配 `accum_grad=8` 会一次都不更新；数据变多后再调回 8。
7. **AISHELL-1 归档不是扁平 wav**：`data_aishell.tgz` 内是 `data_aishell/wav/Sxxxx.tar.gz`
   这样的"每说话人嵌套 tar.gz"，按 `.wav` 过滤外层会一条都找不到（第一次就这么踩空的）。
   另外 ModelScope 上不存在 `aishell1` 这个数据集 id，`MsDataset` 也因缺 `datasets` 依赖不可用，
   正确入口是 `OmniData/AISHELL-1`（镜像 OpenSLR，23.7MB/s）。
8. **流式解压用 `curl | python` 最快**：直接用 `urllib` 从 ModelScope 流式读只有 9.5MB/s，
   `curl -sL URL | python script.py`（脚本读 `sys.stdin.buffer`）能跑满 23.7MB/s；
   脚本拿到目标条数后退出，curl 收到 SIGPIPE 自动停止下载。
9. **解码时关掉 VAD 更快也更干净**：AISHELL 句段本身只有 2~15 秒，`fsmn-vad` 分段纯属开销；
   `++use_vad=false`。真正的瓶颈是 CPU 侧逐条音频读取（约 2.8 条/秒），加大 batch 收效有限。
10. **`merge_ckpt.py` 要连子目录一起复制**：基座目录里的 `Qwen3-0.6B/`（tokenizer，16MB）
    必须带进合并目录，早期版本把目录整个跳过，导致解码时去连 huggingface.co 报错。
11. **别只看 CER 数字**：AISHELL-1 微调 CER 从 3.20% 降到 1.91%，但拆开看 97% 的降幅来自
    "学会把数字写成汉字"这一标注习惯，真实识别 1156 条上 1.91% → 1.95% 基本没动，
    标点输出率还从 83.3% 掉到 0.3%。评估微调必须做归因，否则会把"格式适配"当成"能力提升"。

## 正式训练（扩充数据后）

1. 准备真实录音 + 准确文本标注（专有名词务必写对；建议几十分钟起步，
   覆盖每个专有名词多次出现；音频 16kHz 单声道，单条 3~30 秒）。
2. 生成两列清单（ID 路径 / ID 文本），跑 `fun_asr_nano/scp2jsonl.py` 转 jsonl：
   ```
   python scp2jsonl.py ++scp_file=data/train_wav.scp ++transcript_file=data/train_text.txt ++jsonl_file=data/train.jsonl
   ```
3. 数据量变大后调整 `finetune_local.bat`：`max_epoch`（20~50）、
   `save_checkpoint_interval` / `validate_interval`（按总步数设置，务必小于总步数否则不存盘）、
   `accum_grad` 可提到 8；显存实测很宽裕，`batch_size` 可试探性上调。
4. 数据到几百小时后可解锁更多模块：`audio_encoder_conf.freeze=false` + adaptor 一起训。

## 文件说明

**AISHELL-1 实验（第一部分用）**
- `../dataset/extract_aishell.py` —— 流式按需解压（边下边解，达标即断流）
- `../dataset/build_lists.py` —— 官方标注 CSV × 已解压 wav → wav.scp / text.txt
- `funetune/fun_asr_nano/finetune_aishell.bat` —— AISHELL-1 训练脚本（参数可调，顶部有实测注释）
- `fun_asr_nano/decode_aishell.py` —— 批量解码（支持关闭 VAD 提速，约 2.8 条/秒）
- `fun_asr_nano/decode_aishell.bat` —— 合并 → 解码 → CER 三步一键
- `fun_asr_nano/compute_cer.py` —— CER / 整句正确率 / 逐条变化
- `fun_asr_nano/analyze_gain.py` —— **增益归因**（拆出"标注书写习惯"vs"真实识别"）

**迷你数据流程验证（第二部分用）**
- `build_data.py` —— 从项目音视频 + SRT 自动切分生成迷你数据集
- `funetune/fun_asr_nano/finetune_local.bat` / `lora_local.bat` —— 迷你数据训练脚本
- `fun_asr_nano/decode_ft.py` —— 逐条解码（早期版本，慢，通用）

**公共**
- `fun_asr_nano/merge_ckpt.py` —— **基座 + 微调 checkpoint 合并**（微调权重可用化的关键一步）
- `fun_asr_nano/mem_peak.py` —— 显存峰值测量小工具（轮询 `torch.cuda.mem_get_info`）
- `fun_asr_nano/finetune.sh` / `lora_finetune.sh` / `decode.py` / `scp2jsonl.py` / `model.py`
  —— 官方 FunASR 仓库原版脚本（参考用；`decode.py` 对微调权重不适用，见踩坑 3）
